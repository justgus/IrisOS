# EP-002: Machine and Communications Foundations

**Status:** Closed
**Owner:** System Engineer
**Start Date:** TBD
**Target Close Date:** TBD
**Close Date:** 2026-10-04

**Goal:**
Establish registered Machine representations, in-memory resource descriptors, capability-bearing handles and leases, and Machine-backed Comms protocol execution as required by AR-0024.

**Rationale:**
The migrated Machine and Comms Tasks form one dependency-ordered delivery track under AR-0024.

**Scope:**
- Refract-registered Machine representations
- In-memory descriptors and queries
- Capability-bearing handles and deterministic leases
- Machine-backed Comms and one executable protocol example

**Out of Scope:**
- Machine descriptor persistence
- Wall-clock lease expiration
- Hardware probing and device drivers
- Complete network stacks and remote networking

**Acceptance Criteria:**
- AC-0011: Machine scalar, buffer, and packet primitives, plus processor architecture, register, address-space, and memory-block types, have stable Refract registrations retrievable by canonical identifiers.
- AC-0012: In-memory descriptors represent configured or discovered processor, register-file, memory-region, bus, and device facts; creating or querying a descriptor does not itself grant authority or persist it.
- AC-0013: A Machine handle names a descriptor and its granted capabilities; operations outside those capabilities are rejected.
- AC-0014: A lease has explicit Active, Released, or Revoked state. Release and revocation produce deterministic state and access results without wall-clock expiry.
- AC-0015: A Comms transport and session can reference Machine resources, and the existing loopback path continues to work with its prior behavior.
- AC-0016: Given protocol and transport metadata, compatibility queries return a deterministic compatible or incompatible result, including for missing or contradictory metadata.
- AC-0017: An executable example sends a registered Machine packet over a compatible Machine-backed loopback session, decodes the received frame, and verifies the packet equals the original.
- AC-0018: The protocol example rejects malformed framing and incompatible transports deterministically and requires neither network access nor a hardware driver.
- AC-0019: The repository validation suite passes with the Machine and Comms additions enabled.
